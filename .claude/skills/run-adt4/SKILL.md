# Running ADT4 with run-adt4

`run-adt4` (`dcist_launch_system/bin/run-adt4`) checks the env, writes a temporary tmuxp file
(adding zenoh, bag playback and recording windows as requested) and runs `tmuxp load`. The
session's panes are zsh shells that `source ${ADT4_WS}/install/setup.zsh`.

## Always run inside a fresh zsh with the user's environment

The ADT4 variables live in `~/.zshrc`, and the tool shell may not have them. Run **every**
ADT4 command like this:

```bash
zsh -c 'source ~/.zshrc >/dev/null 2>&1; source ${ADT4_WS}/install/setup.zsh; <command>'
```

Sourcing prints terminal-title escape sequences. Ignore them, or pipe through
`sed 's/\]2;[^]]*\]1;//g'`.

## Step 1: Check the environment (names only, never print values)

Several variables are secrets (passwords, API keys). Check whether they are set, never what they contain:

```bash
zsh -c 'source ~/.zshrc >/dev/null 2>&1
for v in ADT4_WS ADT4_DLS_PKG ADT4_ENV RMW_IMPLEMENTATION \
         ADT4_BOSDYN_USERNAME ADT4_BOSDYN_PASSWORD ADT4_BOSDYN_IP \
         ADT4_OPENAI_API_KEY ADT4_DEEPGRAM_API_KEY \
         ADT4_HERACLES_AGENTS_PATH ADT4_HERACLES_IP ADT4_HERACLES_PORT \
         ADT4_NEO4J_USERNAME ADT4_NEO4J_PASSWORD ADT4_PHX_ROOT \
         ADT4_NTRIP_HOST ADT4_NTRIP_PORT ADT4_NTRIP_MOUNTPOINT ADT4_NTRIP_USERNAME ADT4_NTRIP_PASSWORD; do
  [[ -n ${(P)v} ]] && echo "$v: set" || echo "$v: UNSET"
done; which run-adt4 tmuxp tmux'
```

- The README says **all** of these must be set to *something*, even if only to a dummy value,
  or launch files fail on `$(env ...)`. If one is unset, tell the user. For a variable the
  session doesn't use, offer to pass a dummy inline for this run (`ADT4_PHX_ROOT=none run-adt4 ...`).
  Don't edit `~/.zshrc` without asking. Never invent real secrets.
- `run-adt4` is in `$ADT4_DLS_PKG/bin`. If it isn't on PATH, call `${ADT4_DLS_PKG}/bin/run-adt4`.
- `RMW_IMPLEMENTATION` should normally be `rmw_zenoh_cpp`. `run-adt4` starts the zenoh router
  window itself unless you pass `--no-zenoh`.
- The workspace must be built (`${ADT4_WS}/install/setup.zsh` exists). If a session file is
  missing or stale, regenerate it with the `new-config` skill.

## Step 2: Pick the session and arguments

Sessions are `dcist_launch_system/tmux/autogenerated/<experiment>-<config>.yaml` and are passed
by stem, e.g. `spot_bag-default`. List them with `ls ${ADT4_DLS_PKG}/tmux/autogenerated`. The
README's "Catalog of Supported Launch Configurations" describes the common ones.

Pass everything on the command line so nothing prompts (Claude can't answer prompts):

| Flag | Meaning |
|---|---|
| `-n NAME` | robot name (`ADT4_ROBOT_NAME`), e.g. `hamilton`, `euclid`, base station name |
| `-c ID` | platform id: `topaz`/`smaug`/`apollo` (spot), `phoenix`, `base_station`, ... (`platforms/`) |
| `-o DIR` | output dir. Must not exist, or the user must OK `-f` |
| `-p PATH` | prior map (dir with `hydra/` and `roman/`), for relocalize / prior_dsg / base station |
| `-s` | sim time. Use with `--bag` |
| `--bag PATH [--bag-delay S --bag-start S --bag-rate R]` | play a bag through `ianvs play_rosbag` |
| `-t CSV [--trajectory-args "..."]` | override bag odometry with a trajectory |
| `-r [NAME]` | record a bag (topics from `recording/<NAME>_topics.txt`, default by platform) |
| `--no-namespace-tf` | publish on global `/tf` (default is `/<robot>/tf`, see below) |
| `--rviz-config PATH` | custom rviz config |
| `-y` | skip the "settings correct?" confirm. Only after showing the user the settings |
| `--tmuxp-args "-d"` | **required for Claude**: start detached (no TTY to attach to) |

Rules:
- **`-f` deletes the existing output directory.** Never add it unless the user said that
  directory can be cleared. Otherwise pick a new `-o` path.
- **Sessions with `spot_real`, `phoenix_real`, or `sensors` drive real hardware.** Before
  launching one, confirm with the user and name the robot. Bag, `prior_dsg` (spot_sim) and
  base-station sessions are safe to run without asking.
- TF is namespaced by default (`ADT4_NAMESPACE_TF`): every node uses `/<robot>/tf`. Only the
  base-station sessions merge all robots onto `/<base>/tf` (the `tf_relay` window). Run the base
  station with `-n <base_station_name>`.

## Step 3: Dry run, then launch

Always dry-run first and show the user the env table and windows:

```bash
zsh -c 'source ~/.zshrc >/dev/null 2>&1; source ${ADT4_WS}/install/setup.zsh
run-adt4 spot_bag-default -n hamilton -c topaz -o ~/adt4_output/hamilton_test -s \
  --bag /data/.../recorded_data -y -d'
```

Then launch the same command without `-d`, with `--tmuxp-args "-d"`. The session name is
`adt4_system` (from `base_launch.yaml`). If it already exists, tmuxp will ask to attach. Check
first with `tmux has-session -t adt4_system` and ask the user before killing an existing session.

## Step 4: Check on it

```bash
tmux list-windows -t adt4_system
tmux capture-pane -p -t adt4_system:<window>.<pane> | tail -40   # e.g. adt4_system:core.0
```

Look for `[ERROR]`, `process has died`, Python tracebacks, and missing `$(env ...)` variables.
The `status` window shows node health from `ros_system_monitor`. For ROS checks, run
`ros2 topic list` / `ros2 node list` in the same sourced zsh (same `RMW_IMPLEMENTATION`).

Tell the user how to attach themselves: `tmux attach -t adt4_system`.

## Step 5: Saving and stopping

- **Save the map first** if the user wants it. Press enter in the second (bottom) pane of the
  `core` window, which calls the hydra and roman shutdown services. Pane numbers depend on the
  user's `pane-base-index`, so look the index up with `tmux list-panes -t adt4_system:core`,
  then `tmux send-keys -t adt4_system:core.<idx> Enter`. Or call
  `ros2 service call /dsg_saver/save_dsg dcist_launch_system_msgs/srv/SaveDsg "{save_path: '', include_mesh: true}"`.
  Outputs land in `$ADT4_OUTPUT_DIR/hydra` and `$ADT4_OUTPUT_DIR/roman/roman_map.pkl`.
- Stop with `tmux kill-session -t adt4_system`, but only when the user asks, or for a
  session you started for a test.
